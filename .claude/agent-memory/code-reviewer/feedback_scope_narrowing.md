name: feedback scope narrowing on BLOCKED
description: BLOCKED 판정 후 사용자가 이슈 있는 파일군을 커밋 범위에서 제외하고 나머지만 재검토 요청하는 패턴
type: feedback
---

이전 리뷰에서 여러 파일(예: `.claude/hooks/*`)에 Critical/Major 이슈로 BLOCKED 판정을 받으면, 사용자는 해당 이슈 파일들을 즉시 고치기보다 이번 커밋 범위에서 완전히 제외하고("워킹 트리에 그대로 남겨둠") 문제 없는 나머지 파일만 재리뷰를 요청하는 경우가 있었다 (2026-07-25, git-commit-pusher.md 병합 작업 커밋 범위 축소 사례).

**Why:** 논리적으로 무관한 변경사항을 하나의 커밋에 묶지 않으려는 원자적 커밋 원칙 + 훅 스크립트 수정처럼 별도 처리가 필요한 이슈를 별도 트랙으로 분리하려는 의도.

**How to apply:** 재리뷰 요청 시 "제외 대상"으로 명시된 파일은 절대 손대지 않고, 판정 대상에서도 완전히 제외한다 (Critical/Major 유무 판단에도 포함시키지 않음). 단, 제외된 이슈가 여전히 미해결 상태라는 사실은 [[claude_agents_config_issues]]처럼 memory에 남겨 다음에 그 파일이 diff에 포함될 때 다시 지적할 수 있게 한다. 사용자가 특정 기존 이슈를 "이번 diff의 원인이 아니므로 참고 사항으로만" 남기라고 명시하면, 그 이슈는 판정 근거로 쓰지 않고 각주로만 언급한다.
