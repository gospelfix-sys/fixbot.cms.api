# git-commit-pusher 에이전트에 git-commit 스킬 규칙 병합

## Context

사용자는 `.claude/agents/git-commit-pusher.md` 서브에이전트가 `.claude/skills/git-commit/SKILL.md`(이모지 컨벤셔널 커밋 스킬)의 규칙 내용을 학습·활용하길 원한다. 현재 두 문서는 커밋 메시지 포맷 규칙이 서로 다르게 정의되어 있어, 사용자가 `/git-commit` 스킬로 커밋할 때와 `git-commit-pusher` 에이전트가 커밋할 때 결과물의 스타일(이모지 유무, 줄 길이 기준 등)이 달라지는 불일치가 있다. 이를 하나로 통일해 어떤 경로로 커밋하든 동일한 컨벤션이 적용되도록 하는 것이 목적이다.

`git-commit-pusher`는 `model: haiku`로 동작하는 자동화 에이전트이므로, 규칙을 런타임에 `Skill` 도구로 조건부 호출하게 하기보다 **스킬의 핵심 규칙을 에이전트 프롬프트 본문에 직접 병합**하여 항상 일관되게 적용되도록 한다. 다만 향후 스킬 원본이 바뀌었을 때 추적할 수 있도록 출처 주석은 남긴다.

## 반영할 규칙 (SKILL.md → 에이전트 병합 대상)

현재 `git-commit-pusher.md`의 "4단계: 커밋 메시지 작성" 및 "3단계: 스테이징" 섹션과 `SKILL.md`를 대조한 결과, 다음 항목이 누락/불일치한다:

1. **이모지 컨벤셔널 포맷**: 에이전트는 현재 `<타입>: <제목>`만 사용, 이모지 없음. → `<이모지> <타입>: <제목>` 형식과 SKILL.md의 전체 이모지 맵(`✨ feat | 🐛 fix | ...` 등 40여 종)을 반영.
2. **줄 길이 기준 불일치**: 에이전트는 "제목 50자 이내", 스킬은 "첫 줄 72자 미만". → 스킬 기준(72자, 이모지+타입+설명 포함 전체 첫 줄)으로 통일.
3. **명령형 어조 규칙 누락**: 스킬의 "명령형 어조 (추가 not 추가됨)" 규칙이 에이전트에 없음 → 추가.
4. **스테이지 파일 우선 규칙 누락**: 스킬의 "스테이지된 파일이 있으면 해당 파일만 커밋" 규칙이 에이전트의 3단계 스테이징 절차에 없음 → 추가.
5. **분할 기준 명문화 누락**: 스킬은 "다른 관심사 | 혼합된 타입 | 파일 패턴 | 큰 변경사항"을 명시적 분할 기준으로 제시. 에이전트는 "원자적 커밋"이라는 원칙만 있고 구체적 기준이 없음 → 명시적 기준표 추가.
6. **Claude 서명 금지 규칙 누락**: 스킬은 "커밋에 Claude 서명 절대 추가하지 않음"을 명시. 에이전트에는 이 규칙이 없음 → "안전 규칙 > 절대 하지 않는 것" 섹션에 추가.

에이전트 고유 규칙 중 유지할 것: code-reviewer APPROVED 사전 확인(0단계), 보호 브랜치 경고, force push/reset 금지, 메모리 업데이트 로직 — 이들은 SKILL.md에 없는 내용이므로 그대로 둔다.

## 수정 파일

- `.claude/agents/git-commit-pusher.md` (단일 파일 수정)

### 세부 변경 위치

- **"### 4단계: 커밋 메시지 작성" 섹션 전체 교체**:
  - 형식을 `<이모지> <타입>: <제목>` (전체 첫 줄 72자 이내, 명령형 어조)으로 변경
  - 기존 9개 타입(feat/fix/refactor/style/docs/test/chore/perf/ci) 각각에 대응 이모지 매핑 표기
  - SKILL.md의 전체 이모지 맵을 "확장 타입(선택)"으로 추가하여 breaking change, revert, security(🔒️), db(🗃️) 등 세분화된 상황에 사용 가능하도록 함
  - 예시 커밋 메시지도 이모지 포함 형태로 갱신

- **"### 3단계: 스테이징" 섹션에 규칙 추가**:
  - "이미 스테이지된 파일이 있는 경우, 새로 스테이징하지 않고 해당 파일만 커밋 대상으로 삼는다" 규칙을 최상단에 추가

- **"## 안전 규칙 > 절대 하지 않는 것" 섹션에 항목 추가**:
  - "커밋 메시지에 Claude 서명(Co-Authored-By 등) 추가" 항목 추가

- **새 하위 섹션 "분할 기준" 추가** (4단계 내 또는 3단계 하단):
  - 표 형태로 `다른 관심사 | 혼합된 타입 | 파일 패턴 | 큰 변경사항` 각 기준 설명

- **문서 최상단 또는 4단계 시작부에 출처 주석 1줄 추가**:
  - `> 커밋 메시지 컨벤션은 .claude/skills/git-commit/SKILL.md 기준을 따른다.` — 향후 스킬 원본이 바뀔 때 사람이 추적할 수 있도록 하는 목적의 주석(코드가 아니므로 별도 파일 참조 로직은 만들지 않음)

## 하지 않는 것 (스코프 아님)

- 에이전트의 `tools:` 목록에 `Bash`가 없어 실제 `git status/add/commit/push` 명령을 실행할 수단이 불명확해 보이는 기존 이슈가 발견되었으나, 이는 사용자의 이번 요청("스킬 규칙 학습·활용")과 무관한 별개 사안이므로 이번 작업 범위에 포함하지 않는다. 필요 시 별도로 확인 요청 예정.
- `SKILL.md` 자체는 수정하지 않는다 (에이전트가 스킬을 따라가는 방향).

## 검증 방법

- 수정 후 `.claude/agents/git-commit-pusher.md`의 YAML frontmatter가 깨지지 않았는지 확인 (기존 `description`, `tools`, `model`, `color`, `memory` 필드 유지).
- 실제 커밋 시나리오로 검증하려면, 임의의 스테이징 변경 후 사용자가 "커밋해줘"라고 요청 → code-reviewer APPROVED 이후 `git-commit-pusher` 에이전트가 생성하는 커밋 메시지가 `<이모지> <타입>: <설명>` 형식과 72자 제한, 서명 미포함을 지키는지 육안 확인.
